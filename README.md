# 远程设备固件分批发布控制台

源提示词摘要：发布负责人选择设备范围、固件版本、分批比例和回滚版本，运维设定兼容条件与失败阈值，值班人员监视下载、安装、重启和异常事件；关键发布支持审批、暂停、继续和紧急回滚，过期状态不可误用。

## 技术栈

Angular、TypeScript、Angular Material、NgRx、Angular Router、RxJS、Angular CDK、Transloco。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62026`

## 可用流程

- 创建发布批次并关联设备分组、固件版本、分批比例和失败阈值。
- 批次从草稿、已审批、发布中、暂停到完成或回滚。
- 兼容条件阻止不合格分组加入发布；实时指标由本地遥测模拟驱动。
- 审批、暂停、继续、回滚和状态变化保留审计记录并持久化到 localStorage。

## 逐台进度账

- 设备分组 → 网关 → 设备三级拓扑；批次创建时按灰度比例冻结发布设备清单。
- 回执按「批次 + 设备编号」入逐台台账：每台设备只保留最新结果（`reportedAt` 较新或阶段更靠后者胜出）；同一台设备重复回传标记为重复、只留痕不计账。
- 页面所有台数（有回执/已下载/已装/失败/进度）都是台账的实时投影，不再单独累计，同一台不会算两次。
- 离线期间回执在网关侧积压；网关回网后按时间顺序补报，合并进**尚未结束**的批次，已装好的台数不重算；批次已结束/已回滚时迟到回执一律作废。
- 失败阈值改动后，进行中（发布中/已暂停）批次旧判定失效并按现台账重算（`tallyVersion` 递增），逐台台账与已装台数保留。
- 紧急回滚封存台账；离线期间积压在网关侧的旧回执逐张作废，回网后也不再入账。
